## Карта
- **Движок:** MapTiler (не Mapbox). Причина: у основателя только российская банковская карта, Mapbox требует привязку карты для активации даже бесплатного тарифа; MapTiler даёт бесплатный доступ по email без карты.
- **Стиль:** MapTiler Streets (яркий, живой), не стандартный OpenStreetMap-стиль (слишком жёлтый/пустынный на вид — было явное замечание основателя).
- **3D:** через MapTiler SDK JS (на основе MapLibre GL), рельеф включается через `setTerrain`, доступен как переключаемый режим, не основной вид по умолчанию (тяжелее для слабых устройств).

## Бэкенд
- **Django + Django REST Framework (DRF)** — финальный выбор (заменяет открытый вопрос от Этапа 0, дата: 2026-09-13). Причины:
  - Встроенная админка из коробки — готовая панель для волонтёров/админа (это прямое требование Этапа 1 «Wеб-панель»).
  - Встроенный i18n на три языка (ru/en/tg) — задача «Настроить i18n-инфраструктуру» решается штатным механизмом Django.
  - Встроенная аутентификация и роли пользователей.
  - ORM + миграции — модель данных из раздела 5 PROJECT.md описывается без лишней обвязки.
  - `django.contrib.gis` — родная интеграция с PostGIS для геозапросов.
  - DRF — для API, которое будет потреблять фронтенд (карта, списки мест, маршруты).
  - У основателя уже есть опыт с Python.

## База данных
- PostgreSQL + PostGIS. Причина: нужны геозапросы (ближайшие точки, маршруты).
- **Важное техническое ограничение (дата: 2026-09-14):** PostGIS-движок Django (`django.contrib.gis.db.backends.postgis`) и приложение `django.contrib.gis` требуют GEOS + GDAL на стороне Python-приложения, иначе Django не стартует с ошибкой `ImproperlyConfigured: Could not find the GDAL library`. Поэтому:
  - По умолчанию приложение работает на стандартном `django.db.backends.postgresql` движке (не требует GEOS/GDAL), БД содержит PostGIS-расширение.
  - PostGIS-движок Django включается флагом `USE_POSTGIS_BACKEND=1` на машине/сервере, где установлены GEOS+GDAL (например, через Docker-образ бэкенда).
  - `django.contrib.gis` НЕ добавлять в `INSTALLED_APPS`, пока не понадобятся GIS-фичи — он тоже требует GDAL при импорте.

## Хостинг
- Бюджета на старте нет — бесплатные тарифы.
- **База данных: Neon Free** (дата выбора: 2026-09-14). Причины:
  - Бесплатно без срока (нет 30-дневного ограничения как у Render Postgres).
  - 0.5 ГБ хранилища, 100 CU-часов вычислений в месяц — достаточно для MVP.
  - PostGIS доступен как расширение в БД (включается одной командой).
  - Автоматическое scale-to-zero → при простое приложение потребляет $0.
- **Приложение (Django): Render Free** (дата выбора: 2026-09-14). Причины:
  - Бесплатный веб-хостинг с авто-деплоем из Git.
  - 750 часов в месяц, спин-даун после 15 минут простоя — нормально для previews/MVP.
  - Важно: Render Postgres Free БЕЗОПАСНО использовать НЕЛЬЗЯ (данные стираются через 30 дней) — для БД всегда Neon.
  - GEOS+GDAL (нужны для PostGIS-движка Django) ставятся через Dockerfile/requirements на Render.
- **Локальная разработка: Docker Compose** (`docker-compose.yml` в корне проекта) — `postgis/postgis:16-3.4` образ, PostGIS доступен из коробки.
